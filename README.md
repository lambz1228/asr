# ASR 音频采集小程序 · 快速上手

> 一句话：**双击一个脚本起后端 → 用微信开发者工具导入一个小程序目录 → 就能走通「登录 → 签同意书 → 领文本 → 录音 → 上传 → 审核 → 导出」全流程。**

工程位置：`E:/asr/`

---

## 一、三步跑起来

### 第 1 步：启动后端（首次约 1–3 分钟装依赖，之后秒起）

- **Windows**：双击 `E:\asr\start-server.bat`
- **macOS / Linux / Git Bash**：在 `E:/asr` 下执行

  ```bash
  bash start-server.sh
  ```

看到这一行就成功了：

```
Uvicorn running on http://0.0.0.0:8000
```

自检（另开一个终端）：`curl http://localhost:8000/health` → 返回 `{"status":"ok"}`

> 脚本会自动完成：建 `.venv` → 装依赖 → 由 `.env.example` 生成 `.env` → 以 `--reload` 启动。
> 重复运行是安全的（已存在则跳过建环境和生成 `.env`）。

### 第 2 步：导入小程序

1. 打开**微信开发者工具**（稳定版）。
2. 点「导入项目」→ 目录选 `E:/asr/asr-miniprogram`。
3. AppID 选「**测试号**」或你自己的 AppID（`project.config.json` 里当前填的是 `wx43432dad19c9d452`，按需替换；已关闭域名校验，模拟器可直接连本机后端）。
4. 点「编译」，模拟器出现登录页即成功。

### 第 3 步：走一遍完整演示

**通路 A · 普通用户（采集）**

| # | 操作 | 预期 |
|---|---|---|
| 1 | 点「微信登录（采集员）」 | 自动跳到《语音信息单独同意书》 |
| 2 | 勾选后点「同意并提交」 | 进入「首页」（我的进度 / 我的任务） |
| 3 | 点一条任务 → 录音 → 试听 → 提交 | 提示"上传成功"，并自动跳到下一条 |
| 3b | 底部切到「我的」 | 看到账号 / 角色 / 我的进度；可**切换身份**（仅开发版）或**退出登录** |

**通路 B · 管理员（导入任务 / 审核）**

| # | 操作 | 预期 |
|---|---|---|
| 4 | 返回登录页 → 点「管理员登录（演示）」 | **直接进入首页的管理视角**（管理员不采集，无需签语音同意书） |
| 5 | 首页 →「导入任务」→ 上传 Excel（`序号`/`汉语文本` 两列）或粘贴文本 → 勾选「下发给」采集员 → 导入 | 建成任务包，并按人下发为子任务 |
| 6 | 换采集员账号登录 → 首页「我的任务」 | **直接看到已下发的任务**，照文本录音（未指派的在「公共池」领取） |
| 7 | 首页 →「录音审核」→ 试听 → 通过/退回 | 列表状态更新为"已通过"/"已退回" |
| 8 | 审核台点「导出」 | 生成含音频 + `metadata.csv` + `manifest.json` 的 ZIP |

> 两个身份**共用同一套底部导航**（首页 / 学习资源 / 语言采集 / 我的），登录后角色只决定首页展示的内容，不再切换入口页。
> 第 4 步的"管理员登录"只在本机 dev 模式生效；生产走真实微信登录，角色由后端分配后按角色自动分流。

## 四、真机录音参数验证（你出设备，脚本收数）

```bash
# 在线模式：真机探针上报 → 后端 ffprobe 复核 → 脚本聚合出报告
python tools/verify_recording.py --api http://localhost:8000/api --token <JWT>

# 离线模式：把真机导出的音频放进一个目录，本机直接测
python tools/verify_recording.py --dir ./samples \
  --expect-format aac --expect-sample-rate 16000 --expect-channels 1
```

详细步骤见 `真机录音参数验证清单.md`。
**建议先装好 ffmpeg**（终端能跑 `ffmpeg -version` 即可），否则只能凭文件头判格式，拿不到真实采样率/声道。

## 五、管理员导入任务（格式）

把待录文本整理成 **Excel 两列：`序号` + `汉语文本`**（`.xlsx` 最佳；`.csv` 亦可），在首页「导入任务」里上传即可。模板见 `任务导入模板.csv`。

| 序号 | 汉语文本 |
|---|---|
| 1 | 今天有空吗？我们一起去街上逛逛，买点好吃的回来。 |
| 2 | 手机没电了，我先充一会儿电，等下再和你聊天。 |

- `序号` 列**自动忽略**（只供人工核对，不写入系统，避免跨任务包冲突）；`汉语文本` 为待录文本，**不能为空**。
- 同义表头都认：`汉语文本 / 中文文本 / 文本 / 内容 / 文本内容 / 待录制文本 / 语句 / sentence`。
- 无表头时按「第 1 列序号 + 第 2 列文本」兜底识别。旧版 `.xls` 不支持，请另存为 `.xlsx` 或 `.csv`。

**导入时决定分给谁**（这是"统一下发"的关键）：

| 场景 | 效果 |
|---|---|
| 勾选采集员 + **每人一份**（默认） | 每个采集员各拿**全部文本**，各自录一遍 |
| 勾选采集员 + **轮流分摊** | 文本按顺序均分给各采集员 |
| 一个都不勾选 | 进**公共池**，采集员自己在首页「公共池」领取 |

每条文本在每个采集员名下生成一条**子任务**，采集员登录后在首页「我的任务」里直接看到，无需领取。
接口：`POST /api/admin/packages/import`、列表 `GET /api/admin/packages`、模板 `GET /api/admin/packages/template`。

完整说明（JSON 格式、curl 示例、multipart 参数表、约束）见 **`任务导入格式说明.md`**。

## 六、导出数据集（管理员）

审核台点「导出」，把**已通过**的录音打包成 `dataset.zip`：

```
dataset.zip
├── audio/                     # 每条录音一个文件（优先转码后的 WAV，无则原始 aac/mp3）
│   └── r_xxxxxxxxxx.wav
├── metadata.csv               # 台账：编号 / 文本 / 采集人 / 时间 / 时长 / 采样率 / 声道 / 参数版本 / 审核状态
├── transcripts.txt            # 纯文本台账，每行 `音频编号<TAB>文本`，编号与音频一一对应
└── manifest.json              # 文件清单 + MD5 + 导出时间 + 总条数
```

- 单次 ≤ 1000 条：同步直接返回 ZIP；超过则**异步打包**，前台轮询进度并拿到签名下载链接。
- **完整性校验**：任一录音的音频文件在对象存储中缺失，或 ZIP 内音频数与台账行数不一致，会**中止导出并说明原因**——避免交付"台账有记录、包里没文件"的残缺数据集。
- **留存与清理**：异步导出的 ZIP 会留在对象存储里，默认**保留 7 天**（`.env` 的 `EXPORT_TTL_DAYS`，置 0 关闭）。到期自动删除并置任务状态 `expired`，触发点为「服务启动 / 异步导出完成 / 管理员手动清理」，管理台「审计日志」页底部有一键清理，也会列出各导出包的到期时间。
- 字段含义、示例与下游解析建议见 **`数据集导出说明.md`**。

## 七、常见问题

- **端口 8000 被占用**：改脚本里的 `--port`，同时改 `asr-miniprogram/app.ts` 的 `baseUrl`。
- **真机预览连不上后端**：真机不能用 `localhost`。需把 `app.ts` 的 `baseUrl` 改成你电脑的**局域网 HTTPS 域名**，并在小程序后台配置 request / uploadFile / downloadFile 合法域名。
- **没装 ffmpeg**：转码会降级为 `skipped`，不阻断上传；装上后自动启用真实探测。
- **生产部署**：把 `.env` 的 `ENV` 改成 `prod`，填好 `JWT_SECRET` / `WX_APPID` / `WX_SECRET`，并设 `DEV_MOCK_LOGIN=false`；否则**启动会失败**（刻意的 fail-fast）。需要数据库/存储可用 `docker compose up -d` 起 PostgreSQL + MinIO。
- **导出包自动消失**：这是设计行为——`EXPORT_TTL_DAYS`（默认 7 天）到期会删除对象存储里的导出 ZIP。需要长期留存就把该值调大或置 0，并把 ZIP 拷到别处。
